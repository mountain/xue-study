# 冻结结果的生命周期与引用规则（P1／P2／P3）

2026-09-28 建立。**提问方决定**（原话）：

> 「gram 的方法本来就要从主要方法下降为参考方法，所以它受影响不是那么重要。我们都要整理原生方法上去，
> 所以我认为「用 ERA5 的 sp/sst 进入模型状态」没有问题，状态本来就需要重算，
> 问题是冻结结果进入判定链条的程序如何设定？」

本文就是那个程序。

---

## §0 要解决的是哪三件事被混成了一件

现在文档引用冻结件时**只引 sha256**，于是只能表达三件事里的一件：

| 维度 | 是什么 | 会不会变 | 现在能不能表达 |
|---|---|---|---|
| **字节** | 文件内容（sha256） | **不会变**（冻结） | **能** |
| **效力** | 还能不能当依据：`current` / `reference` / `superseded` | **随时可改**（判定问题） | **不能** ← 缺口 |
| **代次** | 属于哪一代方法、哪一版状态 | 换代时变 | **不能** ← 缺口 |

**引用腐化的根源就是这个缺位**：字节不会腐化，**引用会**。一个仍然正确的 sha256 可以指向一个
**已经不该再作为依据**的产物——2026-09-28 的"矩阵方法降为参考方法"这条声明，当场制造了这个情形。

## §1 P1 · 生命周期台账（`docs/lifecycle.jsonl`，只追加）

```
{"event":"state_set","artifact":"archive/multivariate-l12-v1/model.npz",
 "sha256":"807c46c8…","from":"unregistered","to":"reference",
 "decided_by":"提问方（Mingli Yuan）","date":"2026-09-28","reason":"…原话…",
 "method_generation":"matrix-l12-v1","role_after":"基线（P4a）＋ 独立实现（P4b）＋ 历史留痕",
 "successor":null}
```

**三态及其含义**（不设第四态；需要新含义时先改本文）：

| 状态 | 含义 | 能出现在哪里 |
|---|---|---|
| `current` | 现行依据 | 判定链条的**依据**位置 |
| `reference` | **只作对照用**：基线（要超过的下限）或独立实现（用来抓实现 bug） | 对照句、回归句；**不得**出现在结论句里 |
| `superseded` | 已被取代，只作历史留痕 | 只能在**紧跟取代指针**时出现；任何新判定不得引用 |

**两条硬规矩**：

1. **状态只写在台账里，不写进被冻结的文件。** 冻结件的字节永远不动——否则"冻结"就没有意义了。
2. **台账只追加。** 改变状态是**加一条新记录**（`from`→`to`），不是改旧记录。

## §2 P2 · 引用格式

引用冻结件时三件齐备：

```
路径@sha256:前16位 (代次/状态)
例：archive/multivariate-l12-v1/model.npz@sha256:807c46c89691f34d (matrix-l12-v1/reference)
```

**简写规则**：一处文档可以在**首次出现处**写全，之后写 `model.npz@807c46c8…(reference)` 即可；
但**状态字不得省略**——省略状态正是本规则要禁止的事。

## §3 P3 · 机械检查（`scripts/check_lifecycle.py`）

对全仓库文档扫描 sha256 形态的引用，逐条判定：

| 检查 | 判定 | 违反时 |
|---|---|---|
| **A 可解析** | 该 sha 前缀能在 `docs/lifecycle.jsonl` 或 `evidence/MANIFEST.jsonl` 或某个 `archive/*/manifest.json` 里找到 | `unresolvable` |
| **B 未过期** | 被引件的状态不是 `superseded`；若是，其后 N 字符内必须有 `successor`／`取代` 指针 | `superseded_without_pointer` |
| **C 不越位** | `reference` 件不得出现在**结论句**里（同一句含 `结论／因此／所以／证明／表明／据此／故`） | `reference_in_conclusion` |

**退出码**：默认 `--report` 模式**退出 0**（它是一次普查，旧文档里必然有大量历史引用）；
`--strict` 才非零退出，供引用清理完之后接进 CI。

## §4 代次与状态版本（P5，随 P2 一起用）

每条**验证记录**与每份**汇总**都必须带 `method_generation` 与 `state_version`。
**不同代次不得混进同一汇总行**——这是把项目已立的口径禁则（"两种口径不得混进同一个数"）
机械化成一个字段。`~/xue-assimilation/ledger/verification.jsonl` 与备份账本是最先会踩这个的地方。

## §5 方法换代的判据（P4a；2026-09-28 提问方裁定采用 C-1 ＋ C-4）

**已撤回的错误写法**：要求"原生方法复现矩阵方法到某容差才算过"。
**错在把基线当成了目标**——那等于用被取代的方法给新方法设上限。提问方更正：

> 「原生方法不复现矩阵方法，理论上原生方法比矩阵方法强的多。」

⇒ 判据改为两条（详见 `docs/problem-cards/era5-sp-sst-feasibility.json` 的
`corrections_to_my_procedure_design`）：

| 编号 | 判据 | 为什么它可判 |
|---|---|---|
| **C-1 非退化** | 选阶判据必须有**内部最优**，且该最优对口径扰动稳健 | 矩阵方法**已实测做不到**（E1：`L_total` 单调递减、argmin 落在阶梯端点、无内部极小） |
| **C-4 口径不变量** | 在 4 种网格口径上重做，原生方法的**不变读数显著多于**矩阵方法 | 矩阵方法的关键读数随网格／度量剧烈变化（周期 72／48／24／**无**）；口径矩阵（`63c`）可直接复用 |

这两条**尚未执行**；它们进入判定链条之前，不构成任何结论。
