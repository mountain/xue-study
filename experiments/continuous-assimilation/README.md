## 1. 现在能跑的：只有「采集与冻结」这一层

```bash
cd ~/xue-study/experiments/continuous-assimilation
~/climatetensor-env/bin/python selftest.py        # 离线自检，2026-09-28 实测 22/22
~/climatetensor-env/bin/python orchestrate.py probe    # 现在服务上最新的是哪一次起报
~/climatetensor-env/bin/python orchestrate.py freeze   # 探测 + 冻结最新起报的分析场（f000）
~/climatetensor-env/bin/python orchestrate.py status   # 存量、上限、已冻结次数
```

**首次实跑结果（2026-09-28）**：`gfs.2026092800` 冻结成功，**6,980,832 字节**、12 个变量，
量级核对全过（`tmp2m` 213.15–312.15 K、`prmsl` 93450–106350 Pa）。立刻再跑一次 ⇒ `already_frozen: true`（去重生效）。

**存储预估**：**6.7 MB/次起报**（远低于设计时的 15–25 MB）。每 3 小时轮询 ⇒ 最多 4 次/日 ⇒
**约 27 MB/日 ≈ 10 GB/年** ⇒ 30 GB 硬上限约合 **3 年**。到顶时**大声失败并停止冻结，不删任何东西**。

## 2. 装定时器（服务器上持续运行）

```bash
mkdir -p ~/.config/systemd/user
cp ~/xue-study/experiments/continuous-assimilation/deploy/xue-assim-freeze.* ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now xue-assim-freeze.timer
loginctl enable-linger ubuntu          # 注销后仍继续跑（需要 sudo）
systemctl --user list-timers | grep xue-assim
journalctl --user -u xue-assim-freeze -n 50   # 每次运行的输出
```

**怎么判断它是否健康**（三处，都在数据根里，不在日志里）：

| 看什么 | 在哪 | 含义 |
|---|---|---|
| `ledger/frozen.jsonl` | 一行一次尝试 | `status: written` ＝ 入库；`duplicate_skipped` ＝ 同一次起报已冻结；`refused_range_failure` ＝ 量级闸门拒绝（**要看，不要忽略**）；`refused_storage_cap` ＝ 到顶，等人工处置 |
| `raw/<集合>/<起报>/manifest.json` | 每次起报一份 | 变量清单、**声明单位**、量级核对结果、sha256 |
| `status.json` / `ledger/runs.jsonl` | 每周期一份 | 存量、上限、已冻结次数（`cycle` 才会写 `runs.jsonl`） |

**退出码**：`0` ＝ 周期完成（**没有新数据也是 0**，属正常）；`1` ＝ **工具失败**（闸门或对照坏了）；
`2` ＝ 响亮的运维停止（存储到顶）。**「没有新数据」不是失败。**

## 3. 这一层为什么必须现在就跑

服务对每个集合**只保留最新一次起报**（带版本的目录随时消失），且**没有例行历史**
（`showcase` 只留具名个例）。⇒ **不开始冻结，未来任何月份的月平均都永远拿不回来。**
这是本项目里唯一一件「晚一天做就永久损失一天」的事，也是它与模型层解耦、可以立刻部署的原因。

## 5. 首次实跑抓出的两个真 bug（都已修，留痕）

1. **温度单位错声明**：我把 `tmp850/tmp700/tmp2m` 声明成 `K`，而服务存的是 **`degC`**
   （极区 −23.0 只可能是 °C；−23 K 不可能）。**G2 量级闸门当场拒绝入库**，没有让一个错数字进档案。
   这是本项目**第四次**温度单位陷阱（GDAL/GRIB、Zarr 量化、CFSv2 `tmpsfc`、这次）。
   ⇒ 教训与既有的一致：**数值荒谬时先查单位与解码，不要查物理。**
2. **去重把「被拒的起报」也算作已冻结** ⇒ 声明修好之后**永远重试不了**同一次起报。
   改为只对 `status == 'written'` 去重；被拒的保持可重试（每次尝试都留一行）。

另有一处**测试侧**的教训（值得单独记）：重网格那条不变量我连写了 **5 版测试**才写对，
期间测出 **2 个真 bug**（目的网格纬向盒宽误用 `180/n` 而非 `180/(n−1)`；极区源格权重为负被静默丢弃，
破坏面积守恒到 4e-8）。⇒ **对着物理不变量写测试时，先问「这条不变量真的成立吗」**：
余弦加权的纬度均值**本来就该偏向赤道**，源格存的是**格心值**，所以「等于格心纬度」这条断言从来不该写。

## 6. 明确未做（写在明处，免得读者自己推断）

- **同化不是变分／卡尔曼**：没有背景误差协方差、没有增量求解、没有分析更新；
  它只有**一次观测投影**（观测域上的精确 Gram 最小二乘）。
  *（`casmodel.py` 的旧 docstring 曾声称「与背景预报之差记为增量」——**那是假的**，代码从没做，已改成事实陈述。）*
- 没有**由可分辨性导出的商**（截断阶数仍是**假设的呈现**，见 E1）。
- 没有**逐回路的提升记账**（生日／覆盖层／构造深度／精确残差），没有**和乐**记录。
- 没有集合、没有成员扰动、没有起点敏感性扫描。
- 只冻结 `gfs` 一个集合；`ecmwf`／`aifs`／`ifs` 等未接（同一套适配器，加一行即可，但**每次起报各自占存储**）。
